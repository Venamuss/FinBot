# Правила работы

- Обязательства ТЗ: [test-task-expenses.md](docs/test-task-expenses.md); проектные требования и допущения отделены в [docs/requirements.md](docs/requirements.md).
- Сохраняй архитектуру из [docs/architecture.md](docs/architecture.md): модульный монолит Go, PostgreSQL, React/TypeScript, REST и Telegram с LLM tool calling.
- Выполняй только текущий этап; при подготовке документации код и зависимости не меняй.
- Проверяй `TELEGRAM_ALLOWED_USER_IDS` до LLM, сохранённых ответов и операций бота. Пустой список запрещает бот всем.
- Владельца бери только из Telegram `message.from.id`; все операции бота ограничивай им, включая суммы и уточнения.
- Allowlist действует только в боте; панель без авторизации предназначена для доверенной локальной сети. Таблицу пользователей не добавляй.
- Без диалогового фокуса выбирай последнюю созданную собственную трату; несовпадение старой суммы требует уточнения.
- LLM не определяет права и не получает SQL или административные инструменты; проверяй его аргументы на сервере.
- Используй один конфигурируемый OpenAI-compatible adapter. Реальная проверка локальной LLM дополнительная и не блокирует MVP; автоматического перехода в облако нет.
- Соблюдай [REST-контракт](docs/api.md): ID и суммы — строки; для денег не используй `float`, `spent_at` — календарная дата.
- Сохраняй минимальную архитектуру; новые функции и зависимости обосновывай. Не выдавай проектные допущения за требования ТЗ или согласие пользователя.
- Не записывай секреты и содержимое расходов в журналы или репозиторий.
- Обязательны проверки доступа A/B и запрещённого C; перед сдачей выполни проверки Go, frontend и Compose smoke.
- Отмечай результаты этапов и проверок в [docs/tasks.md](docs/tasks.md); обязательный MVP и дополнительные проверки учитывай отдельно.
